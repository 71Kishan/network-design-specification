# Project Overview

## Background

This project was completed as a college network-design project for a real client. The objective was to assess the existing environment, identify infrastructure and user-performance concerns, and develop a documented network and infrastructure improvement plan.

## Design Process

The documented work progressed through the following design activities:

1. Requirements gathering
2. Existing-environment and performance analysis
3. Logical network design
4. Physical network/infrastructure design
5. Implementation and maintenance planning

The team's work covered the design and planning phases. The installation/maintenance phase was proposed and authorized as a next step, but the team did not perform the physical deployment.

## Requirements Gathering

The team used a site walkthrough and a user survey to understand the environment and identify operational requirements. Survey areas included:

- Personal computer usage
- Ergonomics
- Network performance
- Security

The gathered information was used to connect user-facing problems with infrastructure recommendations rather than selecting equipment in isolation.

## Main Problems Identified

### 1. Network performance

The documented environment used a 50 Mbps symmetrical fiber connection. The project identified delays during periods of high activity and when working with larger cloud-based files.

### 2. Workstation performance

The project documented login and workstation-readiness delays and identified limited workstation memory as a contributor to the user experience, particularly with Microsoft 365 and Epicor workloads.

### 3. Server-rack environment

The existing rack was identified as insufficient in size and cooling capability for the environment and planned equipment.

### 4. Ergonomics

Existing desks had limited adjustability. The proposed design therefore included adjustable sit/stand workstations.

## Design Approach

The project connected measured observations to proposed changes:

**Requirement → Analysis → Design → Physical Plan → Implementation Estimate → Cost Analysis**

This structure is the main portfolio value of the project: it shows a complete infrastructure-planning workflow rather than a standalone network diagram.

## Project Outcome

The client reviewed the project and considered the proposed work as a reference point. The client did not implement the exact solution documented in this repository. Later infrastructure changes were made independently by the client and are outside the scope of this documentation.
